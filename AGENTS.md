# AGENTS.md

Personal dotfiles for bash, zsh, vim, Neovim and ssh, shared across CSCS Alps
clusters, ETH systems, DKRZ Levante and three personal machines. Files are
symlinked into `$HOME` by `install.sh`. See [README.md](README.md) for the
user-facing docs.

## Architecture

Machine differences are resolved at shell startup, not by branching the repo.
`lib/hostinfo.sh` sets two variables and everything else keys off them:

- `DOTFILES_HOST` — the machine (`santis`, `euler`, `surface`, ...)
- `DOTFILES_CLUSTER` — the site (`alps`, `eth`, `dkrz`, `iac`, `local`)

`lib/` is the shared layer, sourced by both `bashrc` and `zshrc`:

| File | Contents | Portability |
| --- | --- | --- |
| `lib/hostinfo.sh` | host/cluster detection, per-host env | strict POSIX, dash-clean |
| `lib/conda.sh` | conda bootstrap | strict POSIX, dash-clean |
| `lib/common.sh` | env, aliases, functions, machine-specific aliases | bash + zsh |

`lib/common.sh` is not dash-clean on purpose: the `cscs-key` function name
contains a hyphen so it can shadow the `cscs-key` binary.

`lib/` is deliberately **not** symlinked. `bashrc` and `zshrc` resolve their own
symlink (`readlink -f "${BASH_SOURCE[0]}"` / `${${(%):-%x}:A:h}`) to find the
repo and source `lib/` from there.

## Conventions

- **Shared logic goes in `lib/`.** If a change would apply to both shells, it
  belongs there, not duplicated into `bashrc` and `zshrc`. That duplication is
  what this structure exists to prevent; it had already caused the two files to
  drift apart.
- **Machine-specific aliases go in `lib/common.sh`**, not `aliases.zsh`, so bash
  and zsh behave identically. `aliases.zsh` is only for zsh-only syntax.
- **Git aliases follow oh-my-zsh names and meanings.** zsh gets ~197 from the
  plugin; `lib/common.sh` mirrors a curated subset for bash. Never define a name
  in `lib/common.sh` with a different meaning than the omz plugin gives it, or
  the two shells diverge. `gll` and the `gsu*` submodule aliases are additions
  that omz does not define.
- **On Alps every cache goes under `$DOTFILES_CACHE_ROOT`** (iopsstor scratch),
  set in `lib/hostinfo.sh`. capstor scratch has a 1M inode quota that uv and
  GT4Py exhaust on their own. A new cache-writing tool gets its variable added
  to that block, never a path in `$HOME` or `$SCRATCH`. Everything under the
  root must be regenerable: scratch is subject to the cleanup policy.
- **Do not hand-edit `p10k.zsh`.** It is generated by `p10k configure`.
- `vim-extensions/` are git submodules. Do not edit their contents.
- Sourcing order in `zshrc` matters: `lib/hostinfo.sh` runs before oh-my-zsh
  (it sets `PATH` and can abort the rc), `lib/common.sh` runs after (so its
  definitions win over the plugins').
- `.editorconfig` covers indentation. Shell files use 4 spaces, JSON and the ssh
  config use 2.

## Control flow details worth knowing

- **`DOTFILES_ABORT_RC`** — `lib/hostinfo.sh` cannot `return` out of the caller's
  rc file, so it sets this to `1` instead and `bashrc`/`zshrc` check it. Used for
  non-interactive Levante (Jenkins) sessions.
- **`DOTFILES_USE_ZSH`** — `0` on Euler only, where `module` misbehaves under
  zsh. Everywhere else `bashrc` ends with `exec zsh`.
- **`bashrc` execs into zsh**, which means `bash -ic '<cmd>'` never runs `<cmd>`
  on most machines: the exec replaces the process first. Use `bash --norc -ic`
  or set `SLURM_JOB_ID=1` when testing bash interactively.
- **conda only runs in interactive shells** (`case "$-" in *i*)`), because
  activating it writes to stdout and corrupts scp/sftp transfers.
- **Never run `conda init` from the install scripts.** `lib/conda.sh` already
  bootstraps conda in both shells, and `conda init` writes *through* the
  symlinks `install.sh` creates, appending its managed block into the repo's own
  `bashrc` and `zshrc`.
- **`install_tools.sh` runs its sudo/conda provisioning only on `local` and
  `iac`.** Alps, Euler and Levante are provisioned with modules or uenv, so the
  script exits before that part on any other cluster. The exceptions are
  `install_delta`, which runs on every host, root or not (it fetches a
  standalone binary from GitHub releases since there is no module or apt
  package for delta on those clusters), and `install_recent_git`, called on
  every host without root (Alps/Euler/Levante and `iac`; `local` upgrades Git
  through the apt PPA instead): the system Git there can be too old for config
  values a newer Git wrote (`merge.conflictstyle=zdiff3`, from 2.35+), so it
  pulls a recent build from conda-forge into `$HOME/.local/opt/git` via a
  throwaway micromamba and symlinks it into `$HOME/.local/bin/git`. Because the
  script runs under `set -u`, every variable `lib/hostinfo.sh` dereferences
  must be guarded (`${SCRATCH:-}`).
- **`install_neovim`, `install_editor_tools`, `install_tmux` and
  `install_fastfetch` also run on every host.** `install_fastfetch` takes the
  "polyfilled" release build, which supports older glibc versions.
  `install_tmux` replaces any tmux older than the latest upstream release with conda-forge's build in `$HOME/.local/opt/tmux`, through the same
  throwaway-micromamba helper (`conda_forge_install`) that `install_recent_git`
  uses.
  LazyVim needs Neovim >= 0.11.2 and the `tree-sitter` CLI, which no module or
  apt package provides, so the official Neovim build goes to
  `$HOME/.local/opt/nvim` (falling back to `neovim/neovim-releases` when the
  official build does not run on an older glibc), and rg, fd, fzf, lazygit
  and tree-sitter go to `$HOME/.local/bin` via `install_release_binary`. Each is
  skipped when already on `PATH`.
- **`nvim/` is linked to `~/.config/nvim`.** It is the LazyVim starter; keep
  local changes in `lua/plugins/` and `lua/config/`. `lazy-lock.json` and
  `lazyvim.json` are written by Neovim through the symlink and are tracked on
  purpose. When `lazyvim.json` gains or loses an extra, update the "Enabled
  extras" line in the README's Neovim section.
- **`$HOME/.local/bin` holds user-local binaries installed outside a package
  manager** (delta, the Claude CLI, ...). `lib/hostinfo.sh` puts it on `PATH`
  for every host, unconditionally. An earlier revision keyed this by
  architecture (`$HOME/.local/$(uname -m)/bin`), since `$HOME` can be shared
  across nodes of differing architecture, but no host ever put that path on
  `PATH`, so it was abandoned; anything installed there now must ship
  arch-specific builds only where that plausibly runs (delta's musl build
  targets exactly the HPC login-node case).
- **`HAS_ROOT` splits that script in two.** `local` is 1, `iac` is 0. Every
  `sudo` call must stay inside the `if (( HAS_ROOT ))` block: co2 and atmos are
  centrally managed and we have no root there, so they run only the
  `$HOME`-local steps (uv, Miniforge, the conda env). `chsh` sits outside the
  block because it changes your own entry, but it is `|| echo`'d since it still
  fails on the LDAP-managed IAC accounts.
- **Never write `sudo apt update && sudo apt upgrade` as one AND-OR list.**
  `set -e` ignores a failure in any position of such a list but the last, so a
  broken `apt update` would fall straight through into `apt install`.
- **The tmux theme lives in `tmux-theme.conf`, sourced only on tmux 3.2+.**
  Catppuccin uses 3.2 features; Levante's RHEL 8 tmux (2.7) would error on
  every start. It is cloned by `install.sh`, not TPM, because it must load
  before `status-right` is built with `-F`: TPM plugins (cpu, battery,
  weather) only substitute placeholders already present in that string.
- **Shift+Enter becomes Alt+Enter (Esc, Enter) for a new line in Claude Code.**
  tmux rebinds it when the terminal reports Shift+Enter as its own key; Windows
  Terminal never does, so `install.sh` merges `windows-terminal.json` into its
  `settings.json` on WSL. Ctrl+J stays with vim-tmux-navigator, except in vim/fzf.
- **The `default` conda env is built from `conda_packages`**, a conda spec file
  (one spec per line, `#` comments) installed from conda-forge. Python is pinned
  there so every machine gets the same interpreter regardless of install date.

## Testing

There is no test suite. Verify changes with:

```sh
# syntax
bash -n bashrc install.sh install_tools.sh lib/*.sh
zsh -n zshrc aliases.zsh
dash -n lib/hostinfo.sh lib/conda.sh     # these two must stay POSIX
jq empty keybindings.json windows-terminal.json

# Neovim, after changing nvim/ or the install steps
nvim '+checkhealth lazyvim'

# host detection, on this machine and simulated
zsh -c 'source lib/hostinfo.sh; echo $DOTFILES_HOST $DOTFILES_CLUSTER'
bash -c 'hostname() { echo eu-login-01; }; source lib/hostinfo.sh; echo $DOTFILES_HOST'

# ssh config changes must not alter resolution
ssh -F config -G santis   # diff against the same output before the change
```

`daint` and `todi` are decommissioned; they must not reappear anywhere.
